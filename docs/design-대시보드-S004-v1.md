# 취소 인사이트 대시보드 (S-004) 설계 메모 v1

> 작성일: 2026-06-05 · 단계: 2단계 신규 기능 · 방식: Quick Flow (설계 → 구현 → 자체 검토·테스트 → 결과 보고)

## 1. 한 줄 정의

분류가 끝난 취소자들을 **"유입경로"와 "이탈 단계"라는 두 안경으로 쪼개어**, 세그먼트별 취소 사유를 비교해 **액션 가능한 인사이트**를 보여주는 화면.

기존 결과 화면의 "전체 인사이트 섹션"이 이미 전체 분포를 보여주므로, 본 대시보드는 **세그먼트 비교(쪼개서 보기)**에만 집중한다. (전체 뷰 중복 제거)

## 2. 합의된 결정

| 항목 | 결정 |
|---|---|
| 비교 축 1 | **유입경로별** (검색·SNS 광고·지인추천·부트텐트 등) |
| 비교 축 2 | **이탈 단계별** (`최종결과` 값 기반: 인터뷰 전 → 중간 → 합격 후) |
| 진입 방식 | 결과 화면의 **"📊 인사이트 대시보드 보기" 버튼 → 새 화면** |
| 레이아웃 | 세그먼트별 **카드 가로 비교**(small multiples), 카드당 취소사유 TOP 3 막대 |
| 최우선 정보 | 화면 상단 **AI 한 줄 결론** + 총 취소/검토필요 숫자 |
| 세그먼트 개수 | 인원 많은 **상위 N개(약 4~5개)** 카드 + 나머지는 **"기타"**로 묶기 |
| 전체(overall) 뷰 | **만들지 않음** (결과 화면 인사이트 섹션과 중복) |

## 3. 화면 구성

```
📊 취소 인사이트 대시보드 · {기수}
총 취소 {N}명 · 검토필요 {M}명
[ 유입경로별 ]  [ 단계별 ]      ← 탭 2개

💬 {AI 한 줄 결론}

┌─ 세그먼트A (n명) ─┐ ┌─ 세그먼트B (n명) ─┐ ┌─ 기타 (n명) ─┐
│ 사유1 ███ 40%     │ │ 사유1 ██ 33%      │ │ ...          │
│ 사유2 ██  25%     │ │ 사유2 ██ 27%      │ │              │
│ 사유3 █   15%     │ │ 사유3 █  20%      │ │              │
└───────────────────┘ └───────────────────┘ └──────────────┘
```

- **유입경로별 탭**: `유입경로` 값으로 그룹핑
- **단계별 탭**: `최종결과` 값을 3~4단계로 매핑해 그룹핑 (왼쪽=일찍 → 오른쪽=늦게)
- 각 카드 = 해당 세그먼트의 **1차 원인(취소사유) 상위 3개** 비율 막대

## 4. 이탈 단계 매핑 규칙 (`최종결과` → 단계)

실제 데이터의 `최종결과` 값 기준 (샘플 193명에서 확인):

| 단계 | 포함되는 최종결과 값(예) |
|---|---|
| 🟢 인터뷰 전 | 신청취소(인터뷰 전), 신청취소(인터뷰 노쇼) |
| 🟡 중간 | 신청취소(본인요청), 신청취소(연락X), 신청취소(조건부적합) 등 |
| 🔴 합격 후 | 합격취소(신청자 요청), 합격취소(연락두절) |

> 매핑 표는 데이터에 새 값이 나올 수 있으므로, 정의되지 않은 값은 "기타 단계"로 안전 처리한다.

## 5. 데이터 의존성 — ✅ 이미 해결됨 (구현 중 확인)

**확인 결과:** 분류 시 각 행의 **원본 엑셀 행 전체**가 `classification_results.source_snapshot`(jsonb)에 이미 저장되고 있다.
- `src/upload/classification-draft.ts`의 `source: row` → 전체 컬럼(유입경로 포함) 보관
- `최종결과`는 `source_snapshot` 안에 포함 (draft의 `resultValue`도 동일 값)
- 결과 API `/api/result/[sessionId]`가 이미 `source_snapshot` + `primary_cause`를 클라이언트로 반환

**결론:** 마이그레이션·파이프라인 수정 불필요. 대시보드는 **기존 결과 API 응답만으로** 집계 가능하다.
- 세그먼트 키: `source_snapshot["유입경로"]`(공백 정규화하여 조회), 단계는 `source_snapshot["최종결과"]` 매핑
- 사유: 기존 `primary_cause`

## 6. 범위 밖 (이번에 하지 않음)

- 전체(overall) 분포 뷰 — 결과 화면 인사이트와 중복
- CSV 다운로드, 로그인/회원가입, 토큰 공유 링크 (별도 2단계 항목)
- 세그먼트 교차(유입경로 × 단계 동시) 분석 — 추후 검토

## 7. 작업 순서 (Quick Flow)

1. ✅ 설계 메모 (본 문서)
2. ✅ 데이터 저장 — 이미 `source_snapshot`에 저장됨 (추가 작업 불필요)
3. ⬜ 집계 로직 (세그먼트별 사유 비율 계산, 순수 함수) + 단위 테스트
4. ⬜ 대시보드 화면 + 결과 화면 진입 버튼
5. ⬜ 자체 검토 + validate(typecheck/lint/build) + 결과 보고
