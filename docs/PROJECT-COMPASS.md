## 1. 한 문장으로: 이건 왜 존재하나

> **채매니저가 기수 종료 후 2~3시간 걸리던 "취소자 수기 분류"를, 15분 안에 끝내고 회의에 데이터로 들고 들어가게 해주는 도구.**

다른 모든 기능은 이 문장에 봉사할 때만 의미가 있다.

---

## 2. 누구를 위한 것인가

- **채매니저** — 교육과정 운영사의 마케팅·모집 담당
- 노션·엑셀은 능숙하지만 **코드는 안 씀**, 노트북으로 사용
- 전형적 상황: **회의 전, 시간에 쫓기며 취소자 엑셀을 빠르게 분석**해야 함
- 원하는 것: **15분 안에 결과 → 팀에 데이터로 공유**

---

## 3. 진짜 핵심 원리 (왜 굳이 AI인가)

엑셀 필터·찾기로 안 되는 이유는 단 하나, **"복합 사유"** 때문이다.

PRD의 이 문장이 프로젝트의 심장이다:

> *"내일배움카드 발급이 늦어져 **타 과정을 신청**하려고 함"*
> → 키워드 필터는 하나만 잡지만, 실제로 필요한 건
> **1차 원인(내일배움카드 이슈)** + **2차 = 신청자가 한 행동(타 과정 신청)** 을 **동시에** 추출하는 것.

**즉 "2차"는 처음부터 _신청자_ 의 행동이다** (운영자가 할 일이 아니다).
→ 2026-06-08, 코드가 "운영자 액션(대기 등록 안내)"으로 흘러간 것을 **"신청자 향후 행동"으로 바로잡아 원래 정의로 복귀**시켰다.

---

## 4. 제품의 뼈대 (이 흐름은 바뀌지 않는다)

```
①업로드 → ②AI가 컬럼을 스스로 파악 → 사람이 승인
   → ③취소값 선택 → ④분류 실행(3건씩 묶음) → ⑤결과 검토·수정 → ⑥노션 복사
```

- **사람이 개입하는 건 딱 두 번**: 컬럼 승인 / "검토 필요" 행 수정. 나머지는 AI.
- 오류가 나도 해당 건만 **"검토 필요"** 로 빼고 **끝까지 돌린다**는 철학.
- 인터뷰·특이사항이 비어 있는 행은 자동 제외.

---

## 5. 분류가 만들어내는 5칸 — 각 칸의 존재 이유

| 칸 | 무엇 | 왜 있나 (목적) |
|---|---|---|
| **1차 원인** | 왜 취소했나 (근본 이유) | 모집 전략의 핵심. "어디서 새는가" |
| **신청자 향후 행동** | 이 사람이 앞으로 뭘 하나 | 경쟁사로 샜나·돌아올까. 이탈 추적 |
| 세부 태그 | 더 구체적인 키워드 | 같은 원인 안에서 패턴 보기 |
| 타 과정명 | 어느 경쟁 과정으로 갔나 | 경쟁 분석 |
| 검토 필요 | AI가 자신 없는 건 | 사람이 마지막 책임 |

→ **1차 원인 + 신청자 향후 행동, 이 두 축이 제품의 본질.** 나머지 3개는 보조.

### 현재 카테고리 (계속 다듬는 중)

- **1차 원인**: 일정 충돌 · 타 과정 신청 · 취업·합격 · 건강 문제 · 내일배움카드 이슈 · 비용 부담 · 개인 사정 · KDT 수강이력 · 커리큘럼
- **신청자 향후 행동**: 다른 과정 신청 예정 · 재지원 의향 · 취업·진학 전념 · 완전 이탈 · 향후 계획 미확인

## 6. 그동안 추가한 것들 — 목적과의 연결

흩어져 보이는 추가 기능들도 한 줄로 꿰인다:

- **노션 복사** → "팀에 공유" 목적
- **인사이트 요약 / 대시보드(S-004)** → "회의에 데이터로 들고 간다" 목적의 연장
  - 단, 이건 **보너스**다. 핵심은 여전히 ①~⑥ 분류 흐름.
- **KDT 수강이력·커리큘럼 카테고리** → "복합 사유를 더 정확히" 목적

---

## 7. 앞으로 안 흔들리는 법 — 새 기능을 판단하는 단 하나의 질문

> **"이게 채매니저가 _15분 안에 회의자료 뽑는 것_ 에 도움이 되나? 아니면 _복합 사유를 더 잘 잡나_?"**

둘 다 아니면 → 이 도구의 일이 아니다.
(예: 자동 이메일 발송, 신청자 관리 등은 다른 도구의 영역)
