# Story 3.3: 인사이트 요약, 추천 액션, 기수 비교 생성 및 결과 저장

Status: review

## Story

채매니저로서,
모든 분류가 완료되면 GPT가 전체 결과를 분석해 인사이트 요약·운영 추천 액션·이전 기수 비교를 생성하고, 결과가 DB에 영구 저장되길 원한다,
그래야 나중에 결과를 다시 확인하거나 팀에 데이터 기반으로 공유할 수 있다.

## Acceptance Criteria

1. **[인사이트 요약]** 모든 행 분류 완료 후 `POST /api/insight`가 GPT-5.5로 주요 패턴 한 단락 요약을 생성한다. (FR24)
2. **[추천 액션]** 응답에는 운영팀을 위한 구체적인 개선 제안 1~3개가 포함되고, 각 제안은 "원인(비율) + 구체적 액션" 형식이다. (FR41)
3. **[이전 기수 비교]** 이전 completed 세션이 있으면 이번 기수 TOP3 1차 원인 비율과 이전 평균 비율을 비교한다. (FR42)
4. **[첫 기수 안내]** 이전 completed 세션이 없으면 "첫 기수입니다. 다음 기수부터 이전 기수와 비교됩니다." 안내를 반환한다. (FR42)
5. **[세션 인사이트 저장]** 생성된 요약/추천/비교는 `sessions.insight_summary`에 JSON 문자열로 저장된다. (FR36)
6. **[세션 완료 저장]** 모든 처리가 완료되면 `sessions.status`가 `completed`, `analyzed_at`이 현재 시각으로 업데이트된다. (FR36)
7. **[시드 비교 검증]** 테스트용 이전 기수 완료 세션 데이터로 TOP3 비교 계산을 검증한다. (FR42)

## Dev Notes

### 이전 Story에서 이어받는 맥락

- Story 3.2의 `/api/classify`는 `classification_results`와 `new_categories` 저장을 끝낸다.
- Story 3.1의 `/analyzing` 화면은 모든 배치 호출 후 `/api/insight`를 호출한다.

### 이번 Story의 핵심 제약

- GPT 응답은 `output_text`에서 읽고 Zod로 검증한다.
- `sessions.insight_summary`는 결과 화면에서 재사용할 수 있도록 JSON 문자열로 저장한다.
- 이전 기수 비교는 `sessions.status === "completed"`인 다른 세션들의 `classification_results.primary_cause` 분포를 기준으로 계산한다.
- 첫 기수 안내 문구는 명세 문구와 동일해야 한다.
