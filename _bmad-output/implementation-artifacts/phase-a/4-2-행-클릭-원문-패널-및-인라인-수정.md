# Story 4.2: 행 클릭 원문 패널 및 인라인 수정

Status: done

## Story

채매니저로서,
검토 필요 행을 클릭하면 원문 전체를 볼 수 있고, 분류 항목을 셀에서 직접 수정하면 자동으로 저장되길 원한다,
그래야 원문을 보면서 분류를 교정하고 별도 저장 없이 계속 작업할 수 있다.

## Acceptance Criteria

1. **[원문 패널]** 결과 테이블 행을 클릭하면 해당 행의 인터뷰 내용 전문과 특이사항 전문이 오른쪽 사이드 패널에 표시된다. (FR28, UX-DR6)
2. **[텍스트 인라인 수정]** 1차 원인, 2차 행동, 세부 태그 셀을 클릭하면 입력 모드로 전환되고 텍스트를 직접 수정할 수 있다. (FR29)
3. **[자동 저장]** 편집 셀에서 포커스가 벗어나거나 Enter를 누르면 `PATCH /api/result/[sessionId]/update` 요청이 전송되어 Supabase에 저장된다. 저장 버튼은 없다. (FR30, architecture-rules.md)
4. **[저장 실패 피드백]** 자동 저장 실패 시 "수정 내용을 저장하지 못했습니다. 잠시 후 다시 시도해 주세요" 토스트가 표시되고 화면 값은 직전 값으로 되돌아간다. (FR30)
5. **[검토 완료 전환]** "검토 필요" 상태인 행을 완료로 변경하면 행 배경과 배지가 완료 상태로 바뀌고 상단 요약 바의 검토 필요/완료 건수가 갱신된다. (FR31, FR25)

## Dev Notes

### 이전 Story에서 이어받는 맥락

- Story 4.1은 `classification_results.interview_content`, `notes`, `source_snapshot`를 저장하고 결과 조회 응답에 포함한다.
- `src/result/result-workspace.tsx`는 이미 `localStorage.session_id`로 결과를 불러오고 요약 바를 계산한다.
- `getResultReviewState`는 `needsReview && !reviewCompleted`일 때만 검토 필요로 계산한다.

### 이번 Story의 핵심 제약

- `window.confirm/alert/prompt`는 사용하지 않는다.
- PATCH Route Handler는 반드시 Zod `safeParse`를 먼저 수행한다.
- Supabase 업데이트에서 `select("*")`는 금지한다.
- 클라이언트는 DB 함수를 직접 import하지 않고 Route Handler만 호출한다.
- API 경로는 `docs/agents/architecture-rules.md`의 결과 업데이트 규칙을 우선해 `/api/result/[sessionId]/update`를 사용한다.
