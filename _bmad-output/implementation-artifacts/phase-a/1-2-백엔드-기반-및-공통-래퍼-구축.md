# Story 1.2: 백엔드 기반 및 공통 래퍼 구축

Status: review

## Story

개발자로서,
Supabase DB 테이블, server-only 클라이언트, 공통 API 핸들러, GPT 클라이언트 래퍼가 갖춰진 환경을 갖고 싶다,
그래야 모든 API 라우트가 코드 중복 없이 안전하게 DB와 GPT에 접근할 수 있다.

## Acceptance Criteria

1. **[server-only 보호]** `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `OPENAI_API_KEY`, `OPENAI_MODEL` 환경 변수가 `.env.local`에 설정되어 있을 때 `shared/supabase/server.ts`를 브라우저 컴포넌트에서 import하면 `server-only` 패키지로 인해 빌드가 실패하고 에러가 발생한다. (NFR6, NFR7)

2. **[DB 스키마]** Supabase 마이그레이션이 적용되어 있을 때 `sessions`, `classification_results`, `new_categories` 테이블이 모두 존재하고 PRD 데이터 구조(UUID PK, timestamptz, 필수 컬럼)와 일치한다.

3. **[API 공통 래퍼]** `lib/api-handler.ts` 공통 래퍼가 구현되어 있고 API 라우트 처리 중 예외가 발생하면 응답이 일관된 형식(`{ error: string }`)과 적절한 HTTP 상태 코드로 반환된다.

4. **[GPT 공통 래퍼]** `lib/gpt-client.ts`에 p-retry 기반 재시도 로직이 구현되어 있고 GPT API 호출이 연속으로 실패하면 최대 3회(1초, 2초, 4초 exponential backoff)를 재시도한 뒤 에러를 throw한다.

5. **[시크릿 비노출]** `npm run build`로 생성된 클라이언트 번들에 `OPENAI_API_KEY` 또는 `SUPABASE_SERVICE_ROLE_KEY` 문자열이 포함되지 않는다. (NFR6, NFR7, NFR11)

## Dev Notes

### Story 1.1에서 이어받는 맥락

- 현재 프로젝트는 `src/app`, `src/components`, `src/shared` 중심 구조로 생성되어 있다.
- 업로드/분류/결과 모듈 간 직접 import 금지 규칙은 여전히 유지된다.
- `scripts/validate-quick.ps1`, `scripts/validate.ps1`는 Windows PowerShell 5.1 호환 수정이 이미 반영되어 있다.

### 이번 Story의 핵심 제약

- **시크릿은 서버 전용**: `OPENAI_API_KEY`, `SUPABASE_SERVICE_ROLE_KEY`는 어떤 클라이언트 컴포넌트에도 노출되면 안 된다.
- **server-only 필수**: `src/shared/supabase/server.ts`는 브라우저 import 시 빌드가 깨져야 한다.
- **Route Handler 공통화**: 이후 `/api/upload/*`, `/api/classify/*`, `/api/result/*`가 공통 에러 응답 형태를 재사용해야 한다.
- **GPT 래퍼는 재시도 기본값 제공**: 향후 분류 API와 인사이트 API가 같은 래퍼를 사용한다.
- **raw SQL 금지**: 마이그레이션 파일 외 런타임 로직에서 raw SQL 사용 금지. 런타임은 Supabase 클라이언트만 사용한다.

### PRD/TRD 기반 데이터 구조 요약

- `sessions`
  - `id uuid primary key`
  - `cohort_name text`
  - `total_rows integer`
  - `excluded_rows integer`
  - `status text`
  - `selected_result_values text[]`
  - `insight_summary text`
  - `analyzed_at timestamptz`
  - `created_at timestamptz`
  - `updated_at timestamptz`
- `classification_results`
  - `id uuid primary key`
  - `session_id uuid references sessions(id)`
  - `row_index integer`
  - `primary_cause text`
  - `secondary_action text`
  - `detail_tags text`
  - `competing_course text`
  - `reasoning text`
  - `needs_review boolean`
  - `review_completed boolean`
  - `created_at timestamptz`
  - `updated_at timestamptz`
- `new_categories`
  - `id uuid primary key`
  - `session_id uuid references sessions(id)`
  - `category_name text`
  - `occurrence_count integer`
  - `created_at timestamptz`

- 환경 변수 로더는 테스트 내에서 `process.env`를 조작 후 복구

- server-only는 모듈 최상단 import 존재와 클라이언트 번들 검색으로 이중 확인
