# Story 3.1: 분류 실행 중 화면 및 진행 표시

Status: review

## Story

채매니저로서,
분류가 진행되는 동안 몇 건이 완료됐는지 실시간으로 확인하고, 실수로 페이지를 벗어나려 할 때 경고를 받고 싶다,
그래야 분류 중 불안감 없이 화면을 지켜볼 수 있다.

## Acceptance Criteria

1. **[초기 진행 화면]** `/analyzing` 페이지에 유효한 `session_id`로 진입하면 현재 단계("취소 사유 분류 중"), 진행 카운터("0건 완료 / N건 전체"), 프로그레스 바가 표시된다. (FR14, FR15, FR16, UX-DR9)
2. **[배치 진행 갱신]** 분류가 3건씩 처리되며 각 배치가 완료될 때 진행 카운터와 프로그레스 바가 갱신된다. (FR14, FR15)
3. **[인사이트 단계 표시]** 인사이트 요약 생성 단계에 진입하면 단계 표시가 "인사이트 요약 생성 중"으로 변경된다. (FR16)
4. **[이탈 경고]** 분류 진행 중 다른 탭 이동 또는 브라우저 종료 시 이탈 경고가 표시된다. (FR17)
5. **[부분 실패 안내]** 특정 배치 실패 시 "N건 검토 필요로 처리됨, 계속 진행 중" 안내를 표시하고 나머지 배치를 계속 진행한다. (FR18)
6. **[지연 안내]** 분류 응답이 지연되면 "GPT 서버 응답 대기 중입니다. 잠시만 기다려 주세요." 안내를 표시한다.
7. **[전체 실패 처리]** 전체 분류 실패 시 재시도 버튼과 업로드 화면으로 돌아가기 버튼을 표시한다. (FR19)

## Dev Notes

### 이전 Story에서 이어받는 맥락

- Story 2.4는 `/api/sessions`로 세션을 만들고 `localStorage.session_id` 저장 후 `/analyzing`로 이동한다.
- 업로드 파일은 브라우저에서만 파싱되므로, 실제 분류할 선택 행은 `/analyzing`에서 읽을 수 있도록 별도 클라이언트 저장 payload가 필요하다.
- `SessionGuard`는 `/analyzing`, `/result`에서 `session_id`가 없으면 `/upload`로 돌려보낸다.

### 이번 Story의 핵심 제약

- 서버 비밀키와 OpenAI 호출은 브라우저에 노출하지 않는다. `/analyzing`은 Route Handler만 호출한다.
- 화면 진행률은 3건 배치 단위로 갱신한다.
- 부분 실패는 전체 실패로 중단하지 않고 검토 필요 처리 안내를 표시한다.
- 카드/프로그레스 바는 기존 `Progress`, `Button`, `Badge` 컴포넌트를 재사용한다.
